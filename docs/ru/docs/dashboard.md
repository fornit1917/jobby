# Дашборд

В Jobby есть необязательный веб-дашборд для наблюдения за фоновыми задачами и управления ими. Он подключается к ASP.NET Core-приложению и открывается в браузере по выбранному вами пути, например `/jobby`.

С помощью дашборда можно:

- видеть, сколько задач находится в каждом статусе, насколько заполнены очереди и какие серверы работают;
- просматривать, фильтровать и сортировать задачи, открывать параметры и текст ошибки любой задачи;
- смотреть задачи по расписанию, их расписания и время следующего запуска;
- запускать запланированные задачи немедленно, повторять упавшие, отменять и удалять задачи;
- создавать обычные задачи и задачи по расписанию;
- находить группы последовательного выполнения, заблокированные упавшей задачей, и разблокировать их.

Интерфейс доступен на английском, русском и бразильском португальском языках, в светлой и тёмной темах.

## Установка

Добавьте пакет дашборда в приложение, которое будет его показывать:

```bash
dotnet add package Jobby.Dashboard
```

Дашборд читает задачи из хранилища Jobby, поэтому приложению также нужен пакет `Jobby.Postgres`. Используйте одну и ту же версию всех пакетов Jobby.

Если дашборд нужно защитить встроенной проверкой логина и пароля, установите ещё один пакет:

```bash
dotnet add package Jobby.Dashboard.Authorization.Basic
```

## Подключение

Нужны три вызова: добавить дашборд и указать, кому он доступен; подключить хранилище с задачами; выбрать адрес дашборда.

```csharp
using Jobby.Dashboard;
using Jobby.Postgres.Dashboard;

// 1. Добавляем дашборд и указываем, кому он доступен (см. раздел "Управление доступом")
builder.Services
    .AddJobbyDashboard()
    .AllowAnonymous();

// 2. Подключаем хранилище с задачами
builder.Services.AddJobbyPostgresDashboardStorage(dataSource);

var app = builder.Build();

// 3. Выбираем адрес дашборда
app.MapJobbyDashboard("/jobby");
```

Теперь дашборд доступен по адресу `/jobby`. Можно выбрать любой путь, кроме корня сайта (`/`).

`MapJobbyDashboard` работает так же, как остальные методы `Map...` в ASP.NET Core. В приложении с классом `Startup` вызывайте его внутри `UseEndpoints`. К его результату можно добавлять соглашения для эндпоинтов, например `.RequireHost("jobs.internal")`. Вызывайте его у самого приложения, а не у группы маршрутов; путь может состоять из нескольких сегментов, например `/admin/jobby`. Эндпоинты дашборда не попадают в OpenAPI-документ (Swagger) приложения.

Если источник данных зарегистрирован в контейнере зависимостей, например через `AddNpgsqlDataSource`, вместо самого источника данных передайте функцию, которая берёт его из контейнера:

```csharp
builder.Services.AddJobbyPostgresDashboardStorage(
    sp => sp.GetRequiredService<NpgsqlDataSource>());
```

Если для Jobby заданы своя схема или префикс таблиц, передайте те же значения хранилищу дашборда, иначе дашборд будет искать задачи не в тех таблицах:

```csharp
// Настройка Jobby
config.UsePostgresql(pg =>
{
    pg.UseDataSource(dataSource);
    pg.UseSchemaName("jobs");
    pg.UseTablesPrefix("jobby_");
});

// Хранилище дашборда: те же схема и префикс
builder.Services.AddJobbyPostgresDashboardStorage(dataSource, o =>
{
    o.SchemaName   = "jobs";
    o.TablesPrefix = "jobby_";
});
```

### Полный пример

Приложение, в котором работает Jobby и дашборд открыт без аутентификации. Такой вариант подходит только для локальной разработки:

```csharp
using Jobby.AspNetCore;
using Jobby.Core.Interfaces;
using Jobby.Dashboard;
using Jobby.Postgres.ConfigurationExtensions;
using Jobby.Postgres.Dashboard;
using Npgsql;

var builder = WebApplication.CreateBuilder(args);

var connectionString = builder.Configuration.GetConnectionString("Jobby")
    ?? throw new InvalidOperationException("Connection string 'Jobby' was not found.");

await using var dataSource = NpgsqlDataSource.Create(connectionString);
builder.Services.AddSingleton(dataSource);

builder.Services.AddJobbyServerAndClient(jobby =>
{
    jobby.AddJobsFromAssemblies(typeof(Program).Assembly);
    jobby.ConfigureJobby((sp, config) =>
    {
        config.UsePostgresql(sp.GetRequiredService<NpgsqlDataSource>());
    });
});

builder.Services
    .AddJobbyDashboard()
    .AllowAnonymous();

builder.Services.AddJobbyPostgresDashboardStorage(dataSource);

var app = builder.Build();

app.Services.GetRequiredService<IJobbyStorageMigrator>().Migrate();

app.MapJobbyDashboard("/jobby");
app.Run();
```

## Управление доступом

Дашборд показывает параметры задач и позволяет изменять задачи, поэтому нужно явно указать, кому он доступен. При добавлении дашборда выберите ровно один из вариантов ниже. Если не выбран ни один вариант или выбрано несколько, приложение не запустится.

Есть два уровня доступа:

- **чтение** - открыть дашборд и просматривать всё, что в нём есть;
- **управление** - дополнительно выполнять действия: запускать, повторять, отменять, удалять и создавать задачи, разблокировать группы.

Если задано только одно правило, оно применяется к обоим уровням.

### Анонимный доступ

Просматривать задачи и управлять ими может любой, кому доступен адрес. Используйте этот вариант только для локальной разработки.

```csharp
builder.Services.AddJobbyDashboard().AllowAnonymous();
```

### Политика авторизации приложения

Если в приложении уже настроены аутентификация и именованные политики авторизации, используйте их. Вторая политика необязательна и относится к действиям управления.

```csharp
builder.Services
    .AddJobbyDashboard()
    .RequireHostPolicy("JobsRead", "JobsManage");
```

### Политика, заданная при добавлении дашборда

Требования можно описать прямо при добавлении дашборда, не регистрируя именованные политики:

```csharp
builder.Services
    .AddJobbyDashboard()
    .RequireAuthorization(
        read   => read.RequireRole("jobby-read"),
        manage => manage.RequireRole("jobby-manage"));
```

### Логин и пароль

Для приложения без собственной аутентификации пакет `Jobby.Dashboard.Authorization.Basic` добавляет проверку логина и пароля (HTTP Basic-аутентификация). Браузер запрашивает их при открытии дашборда.

```csharp
using Jobby.Dashboard.Authorization.Basic;

builder.Services
    .AddJobbyDashboard()
    .AddBasicAuth(o =>
    {
        o.Username     = "admin";
        o.PasswordHash = builder.Configuration["JobbyDashboard:PasswordHash"]
            ?? throw new InvalidOperationException("JobbyDashboard:PasswordHash is required.");
    });
```

Пароль не хранится в открытом виде. Один раз вычислите его хеш и сохраните в конфигурации приложения:

```csharp
string hash = Jobby.Dashboard.Authorization.Basic.PasswordHasher.Hash("your-password");
```

Хеш вычисляется по алгоритму PBKDF2 (HMAC-SHA256, 210 000 итераций, случайная соль длиной 16 байт). Результат - строка в собственном формате Jobby, в которой также записаны соль и число итераций, поэтому хеш, полученный другим инструментом, не подойдёт: всегда используйте `PasswordHasher.Hash`.

При Basic-аутентификации пароль передаётся с каждым запросом, поэтому открывайте дашборд только по HTTPS.

### Логин и пароль вместе с другой схемой

Чтобы принимать и логин с паролем дашборда, и, например, JWT-токены приложения, зарегистрируйте Basic-схему через `AddBasicAuthScheme` и перечислите обе схемы в политике:

```csharp
using Jobby.Dashboard.Authorization.Basic;
using Microsoft.AspNetCore.Authentication.JwtBearer;

builder.Services
    .AddJobbyDashboard()
    .AddBasicAuthScheme(o =>
    {
        o.Username     = "admin";
        o.PasswordHash = builder.Configuration["JobbyDashboard:PasswordHash"]
            ?? throw new InvalidOperationException("JobbyDashboard:PasswordHash is required.");
    })
    .RequireAuthorization(p => p
        .AddAuthenticationSchemes(
            JobbyDashboardBasicDefaults.Scheme,
            JwtBearerDefaults.AuthenticationScheme)
        .RequireAuthenticatedUser());
```

### Полезно знать

- Правила доступа защищают данные и действия. Саму страницу можно загрузить и без аутентификации, но данные на ней появятся только после проверки доступа.
- В приложении, созданном через `WebApplication.CreateBuilder`, всё работает сразу. Если конвейер обработки запросов собирается вручную, вызовите `app.UseAuthentication()` и `app.UseAuthorization()` до вызова `MapJobbyDashboard`, иначе правила доступа применяться не будут.

## Настройки

`AddJobbyDashboard` принимает настройки дашборда:

```csharp
using Jobby.Core.Models.Dashboard;

builder.Services
    .AddJobbyDashboard(o =>
    {
        o.RefreshInterval = TimeSpan.FromSeconds(10);
        o.ReadOnly        = true;
        o.DefaultLanguage = DashboardLanguage.Russian;
    })
    .RequireHostPolicy("JobsRead");
```

| Настройка | По умолчанию | Описание |
|---|---|---|
| `RefreshInterval` | 5 секунд | Как часто открытые страницы обновляют данные. `null` отключает автообновление; кнопка **Обновить сейчас** продолжает работать. |
| `StaleServerThresholdSeconds` | 300 | Сервер показывается как не отвечающий, если от него не было heartbeat-сигнала дольше этого числа секунд. |
| `ReadOnly` | `false` | При `true` дашборд только отображает данные: все действия скрыты и отклоняются. |
| `DefaultTimeZone` | `null` | Часовой пояс отображаемого времени. `null` означает часовой пояс браузера пользователя. |
| `DefaultDateStyle` | `Iso` | Формат даты: `Iso` (2026-11-24), `DayFirstSlash` (24/11/2026), `DayFirstDot` (24.11.2026), `MonthFirstSlash` (11/24/2026). |
| `DefaultTimeStyle` | `H24WithSeconds` | Формат времени: `H24`, `H24WithSeconds`, `H12`, `H12WithSeconds`. |
| `DefaultLanguage` | `English` | Язык интерфейса: `English`, `Russian`, `PortugueseBrazil`. |

Часовой пояс, форматы даты и времени и язык - это только значения по умолчанию. Каждый пользователь может изменить их в верхней панели дашборда; выбор запоминается в браузере.

Время показывается вместе со смещением от UTC, например `2026-11-24 12:10:16 UTC+2`, поэтому всегда видно, к какому часовому поясу оно относится.

## Работа с дашбордом

### Обзор

Стартовая страница показывает текущее состояние:

- **Задачи** - количество задач в каждом статусе; по щелчку открывается список этих задач;
- **Задачи по расписанию** - сколько задач по расписанию ожидает следующего запуска и сколько выполняется сейчас;
- **Очереди** - для каждой очереди количество незавершённых задач и общее количество задач;
- **Состояние серверов** - Jobby-серверы и время их последнего heartbeat-сигнала;
- **Требует внимания** - заблокированные группы, упавшие и замороженные задачи.

### По расписанию

Список [задач по расписанию](./jobs-schedule): расписание в понятном виде, очередь, статус, следующий запуск и время последнего завершения. Задачу по расписанию можно запустить раньше срока или удалить, а также создать новую.

### Задачи

Список обычных задач (не по расписанию). Его можно фильтровать по статусу, очереди, имени задачи и запланированной дате запуска, а также сортировать по имени, статусу, запланированному времени запуска и времени создания. Для задачи из [группы последовательного выполнения](./sequential-execution#группы-последовательного-выполнения) в списке показан идентификатор группы. По щелчку на задаче открываются сведения о ней: идентификатор, группа, время создания и запусков, количество попыток, сервер, параметры и текст ошибки.

### Очереди

Для каждой очереди показано, сколько в ней задач в каждом статусе, сколько незавершённых и сколько всего. Очередь можно развернуть и увидеть первые незавершённые задачи, а можно открыть и посмотреть отдельно незавершённые или все её задачи.

### Заблокированные группы

Если задача из [группы последовательного выполнения](./sequential-execution#блокировка-группы-при-ошибке) окончательно упала, группа может быть заблокирована, а остальные её задачи заморожены. На странице перечислены такие группы и задачи, которые их блокируют. Действие **Запросить разблокировку** удаляет блокирующую задачу, после чего замороженные задачи группы снова планируются к запуску.

### Действия

Действия доступны пользователям с доступом на управление, если настройка `ReadOnly` не установлена в `true`. Чтобы случайно ничего не нажать, пользователь может переключить свой дашборд в режим **Только чтение** переключателем в верхней панели.

| Действие | К чему применимо | Результат |
|---|---|---|
| Запустить сейчас | Запланированные задачи, включая задачи по расписанию | Задача запускается, как только её сможет взять сервер, не дожидаясь запланированного времени. |
| Повторить | Упавшие задачи | Задача планируется заново, счётчик попыток сбрасывается. |
| Отмена | Запланированные и ожидающие задачи | Задача удаляется до начала выполнения. |
| Удалить | Завершённые, упавшие и замороженные задачи; задачи по расписанию | Задача удаляется. Удалённая задача по расписанию больше не запускается. |
| Создать задачу, Создать задачу по расписанию | - | Добавляется новая задача, см. ниже. |
| Запросить разблокировку | Заблокированные группы | Группа разблокируется, её замороженные задачи снова планируются к запуску. |

Замороженную задачу нельзя повторить отдельно, потому что её группа всё ещё заблокирована: вместо этого запросите разблокировку группы (**Запросить разблокировку**). Задачу, которая блокирует группу, тоже нельзя ни повторить, ни удалить.

Досрочный запуск задачи по расписанию не создаёт её копию: задача просто выполняется раньше, а следующий запуск затем рассчитывается по расписанию как обычно.

### Создание задач

Кнопки **Создать задачу** на странице **Задачи** и **Создать задачу по расписанию** на странице **По расписанию** открывают форму со следующими полями:

- **Задача** - одна из задач, зарегистрированных в приложении;
- **Параметры** - команда задачи в формате JSON, например `{"Email": "user@example.com"}`. Если JSON не удаётся прочитать, форма показывает ошибку. Со стандартным сериализатором Jobby регистр в именах свойств не важен (подойдёт и `email`, и `Email`), а неизвестные свойства игнорируются, поэтому внимательно проверяйте имена. Если приложение задаёт для Jobby собственный сериализатор или настройки JSON, параметры читаются строго по их правилам;
- **Очередь** - необязательное поле; если оставить его пустым, задача попадёт в очередь, заданную для неё по умолчанию;
- **Cron-выражение** - для задачи по расписанию;
- **Уникальная по имени** - для задачи по расписанию. С этим флажком задача создаётся эксклюзивной: если эксклюзивная задача по расписанию с тем же именем уже есть, вместо создания новой обновится существующая. Снимите флажок, чтобы добавить ещё одно, независимое расписание. См. [Эксклюзивность](./jobs-schedule#эксклюзивность).

Задача, созданная в дашборде, ничем не отличается от задачи, созданной из кода через `IJobbyClient`.

Создавать задачи можно, если приложение, которое показывает дашборд, регистрирует Jobby через `AddJobbyServerAndClient`, а задачи - через `AddJob` или `AddJobsFromAssemblies`. Если задачи не зарегистрированы, кнопок создания не будет.

## Большие таблицы задач

Для подсчёта задач по очередям и статусам приходится читать всю таблицу задач. Чтобы это не нагружало базу данных, когда дашборд открыт у многих пользователей, результаты подсчёта кешируются на короткое время. Это время задаётся настройкой `CountsCacheDuration` хранилища дашборда (по умолчанию 2 секунды):

```csharp
builder.Services.AddJobbyPostgresDashboardStorage(dataSource, o =>
{
    o.CountsCacheDuration = TimeSpan.FromSeconds(4);
});
```

Поэтому числа на страницах **Обзор** и **Очереди** могут отставать на это время. Задавайте значение меньше `RefreshInterval`. Списки задач и сведения о задаче всегда читаются напрямую из хранилища.

На очень больших таблицах страница **Задачи** работает быстрее всего с сортировкой по умолчанию (по запланированному времени запуска). Сортировка по другому столбцу, поиск по имени и фильтр по дате работают медленнее.

## Запуск в нескольких экземплярах

Дашборд не хранит пользовательские сессии на сервере, поэтому приложение может работать в любом количестве экземпляров за балансировщиком без привязки пользователя к экземпляру (sticky sessions).

Если действия включены, остаётся одна настройка: экземпляры должны использовать общие [ключи ASP.NET Core Data Protection](https://learn.microsoft.com/aspnet/core/security/data-protection/configuration/overview), как и любое ASP.NET Core-приложение с формами. Иначе запрос на действие, попавший на другой экземпляр, будет отклонён.
